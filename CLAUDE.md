# wugs — agent handoff & working rules

**What this is:** the platform core for a modular, local-first linguistics tool suite ("THE tool suite for every linguist"). Working name of the fieldwork kit: **Tongues**. This repo is the Rust engine; UI and kits come later.

## Hard rules (from the decision log — do not violate)
- **The op log is the only source of truth.** `log/<scope>/<device>.jsonl`, append-only, each device writes only its own file. Never rewrite history; never hard-delete (tombstones only).
- **SQLite is a disposable projection.** The only repair path is delete + replay. No code may write the projection except the projector in `wugs-projection` / the facade in `wugs-core`. No "just this once" direct writes.
- **All writes go through domain intents** (`wugs-core::Txn`), which emit primitive ops (`create`/`set`/`delete`/`restore`/`text-edit`) sharing a `txn` id.
- **Validators never block local work** (warn-only locally; `hold` applies to incoming sync via SAVEPOINT quarantine).
- **Restricted data must not cross scope boundaries** in sync. ACL enforcement belongs in the sync layer, not the UI.
- **The repository is public** (since 2026-11-10; pre-release history in the private `judecutler/wugs-archive`). Never commit real field data, recordings, consent records, keys or personal paths; test data is synthetic or openly licensed. PR numbers up to #38 in the docs are archive PRs; link public PRs in full.
- **Modular & swappable:** crates are decoupled; anything kit-specific stays out of the core crates. Tools = views over shared data; kits = manifests (`kits/*/kit.toml`).
- **Features, not models** (owner, 2026-11-10; `docs/design/PACKAGES.md`): feature code asks for a capability (`phone-transcription`, `acoustic-analysis`, …), never a named model; what powers it is a package (manifest + runtime adapter) the person can switch. No feature may hard-code one model or one external program as the only way to do its job.

## Prefer existing tools (owner guidance, 2026-11-08)
Where a maintained library, format or tool already does the job, use it rather than building our own — at the edges and in the app. The zero-dep core below is the one deliberate exception (archival longevity for the format-bearing crates); everything else should lean on the ecosystem (e.g. rustls/ed25519-dalek/cpace for auth, loro for text CRDTs, Tauri for the shell, existing parsers and viewers where they fit).

## Dependencies: zero-dep core, deps only at the edges
The first sessions had **package registries blocked**, so the core was built as **zero-dependency Rust** + FFI to the system `libsqlite3`. Since 2026-11-07 crates.io and npm are reachable. The owner chose to keep the core crates (`wugs-model`, `wugs-oplog`, `wugs-projection`, `wugs-validate`, `wugs-core`, `wugs-xml`) zero-dep on purpose (archival longevity, no supply chain) and to add dependencies only in edge crates (UI shell, transport, Loro integration). The swappable pieces, if a dep ever earns its place:
- `wugs-model/src/json.rs` — hand-rolled JSON (swap for `serde`/`serde_json` when installs work, if desired)
- `wugs-model/src/id.rs` — own ULID impl (swappable for `ulid` crate)
- `wugs-sqlite` — thin FFI wrapper. Already swapped to bundled SQLite (`libsqlite3-sys` with `bundled`, 2026-11-08) so Windows builds. This gives the core one transitive crates.io dependency (`libsqlite3-sys` and its build-time `cc`/`pkg-config`/`vcpkg`), so "zero-dep" now means `wugs-model`, `wugs-oplog` and `wugs-xml`; every crate that links `wugs-sqlite` carries that one dependency; moving to `rusqlite` remains a possible later step
- NFC normalization runs at entry through the `wugs_model::Normalizer` seam (`wugs-unicode` implements it; without it text stores as typed, and replay never re-normalizes because the log is the truth as written). Engines are supplied at open (`Project::open_with(root, actor, Engines { merger, normalizer })`, `open_joined_with`), so no open path can forget one; the desktop shell builds them in one `engines()` function used by open, create and join. NFD text already in a user's log stays as written; the projection compares through the normalizer (lookup keys, validator #1), so it still matches, and a cache built with the other normalizer choice is wiped and replayed. Alphabet-order sort keys with digraph units live zero-dep in `wugs_model::sortkey`; ICU tailorings are the future edge upgrade.
- `text-edit` ops merge through the `wugs_model::TextMerger` seam. `wugs-text` (edge crate) implements it with the `loro` crate; a build without it still works on the spec's degradation path (LWW on `resolved`), per DATA-MODEL §2.3.

## Projection note
v0 uses a generic `entities` + `fields` (EAV) projection rather than one table per entity kind (DATA-MODEL §8). That's deliberate: the projection is disposable. **FTS5 search is in** (PR #9): `search_fts` over the language-bearing fields (unicode61, diacritics folded both ways), maintained by the projector, queried via `Projection::search` (user text only, never FTS syntax), plus the `fields(field, value)` ref index. Typed tables remain deferred: gates pass (p95 87µs) and the trigger to build them is a real tool query they'd serve or projection size (643 MB at 500k ops). Treat DATA-MODEL §8 as the target.

## Known follow-ups from the first tool pass (small, real, non-blocking)
- **One scope per txn is a convention, not enforced**: the importers keep it (tested in wugs-elan and wugs-flex), but `Txn` accepts ops of any scope, and scope-filtered sync would split a mixed txn.
- **Tier `participant` model:** ELAN's participant is free text; the spec's bool + `ref:prs?` doesn't fit. wugs-elan stores `x.elan.participant` for now — reconcile in DATA-MODEL when the Person workflow lands.
- **TierDef has no ordering field**; wugs-elan uses `x.elan.order`. Consider a real `pos`.
- **Bulk ingest fsyncs per txn** — fine for sync-sized batches, slow for 40k-txn imports; batch fsync behind one flag if it ever hurts.
- **FLEx not carried in v0** (counted per element in each import report's `not_carried`): LIFT examples, notes, pronunciations, relations, traits, fields, etymologies, subsenses, and `<span>` markup (span *text* is kept, in order); FlexText children of `<paragraph>` other than `<phrases>`. FlexText `<item>`s of every type are kept verbatim. A real donated FLEx project through import→export→diff is still PRD gate 3.
- **FlexText phrase text**: when a phrase has no `txt` item, its `content` is derived from the words, and edits to that `content` are not exported (FLEx rebuilds it from words anyway).
- **Degraded text-edit values wash out**: text written by the LWW degradation path (no merger, or a corrupt loro payload) is not in the loro document, so the next merged edit from another device replaces it; a local edit on the same device keeps it. Surface in the conflict UI when that lands.
- **All-pending updates re-seed**: if every stored update of a field is still pending on missing deps, a local edit starts from an empty doc without a genesis and the text can double once the deps arrive. Only reachable when sync delivers txns out of causal order (a held txn in quarantine); the ingest retry (PR #8) shrinks the window but does not close it.
- **Unset access = open is DECIDED** (owner, 2026-11-08; DATA-MODEL §4, DECISIONS): simple sharing wins over fail-closed; access levels are opt-in machinery.
- **Session refs dangle across scopes**: ops carry people-scope session ids into open scopes; peers without the people scope see an unresolvable ref. Content does not leak; the provenance is just unreadable there.
- **Sync auth v1 is BUILT, engine and shell** (`wugs-auth` + `wugs-net`, security-reviewed, takeover scenario regression-tested; shell screens reviewed too): flat-roster CPace pairing, TLS 1.3 raw public keys, members sync everything, guest read-only, hash-chained revocation (forks fail closed into `contested`). `serve_open`/`sync_open` are the unauthenticated test/dev paths. Small remainders: no cancel for an unused pairing code (its port lingers ≤120 s after a project change; pair_finish refuses it); the 5-minute per-session watchdog deadline may need raising/configuring for very large projects on weak links; the single-instance hand-off and window-close layout flush passed on-screen on Windows 2026-11-08. Dockview tab drag between groups never worked on Windows: Tauri's native drop handler swallowed every HTML5 drag; it is off since 2026-11-11 (`dragDropEnabled: false`, DECISIONS), and a mouse-driven tab drag passes in headless Chrome, but the Windows window still needs the owner's hand check. Window-state restore and the relocation banner need one on-screen check on the ThinkPad.
- **Wire responses are checked against the request**: the requester fails a pull on groups or windows for an unasked scope, windows outside the asked groups, an op of another scope, or a txn with no op in an asked window (the widening rule, checked as the responder computes it). The session version is enforced via ALPN (`wugs/3`; bumped from `wugs/2` when ops gained `heads`) before any frame.
- **Retry cost**: every ingest re-validates every held txn until a fixpoint; worst case is a pass per txn when holds unblock in reverse order. Fine at field scale; index by blocking target if a real project holds hundreds.
- **Wire transfer can carry known ops**: a txn-widened window may include ops the requester already has; they are dropped on arrival (counted in ops_dropped_known). Send per-window op-id digests if bandwidth ever matters on real field links.
- **Projection catches up at open**: a crash between a commit's log append and its savepoint release (both commit paths) leaves ops the cache lacks; every open of an existing cache applies them through the replayer, reading each log file from where the last read stopped (`log_ends`; 7–9 ms warm open at 100k ops, release), counts them in `Project::caught_up()`, and releases holds a crashed retry had logged; a rebuild still reads everything and refuses corrupt lines, the catch-up does not, and an op it cannot apply rolls the catch-up back and the project opens as it was (never a failed open). The first open after upgrading reads the whole log once. Crashes are simulated in tests (ops appended to the log, an earlier cache restored), never a killed process. A torn tail followed by a later append still merges into one bad line and loses that op.
- **Text replay is quadratic per field** (each text-edit re-imports all its field's updates; measured ~6 s replay for one field with 1000 edits, release build). Fine for transcription-scale edit counts; cache a per-field loro snapshot in the projection if a real project hurts.
- **Pending-newest text stamp**: when a field's newest update cannot apply yet, the field still carries the newest op's hlc while showing older text. Deterministic and convergent, but the staleness is invisible; surface it with the conflict UI work.
- **Seal follow-ups**: CLDF export; XSD-valid IMDI (one Session per METATRANSCRIPT + MDGroup, with a Corpus file) once Person/Session data is richer; a real project `title` field (olac.xml falls back to "wugs project <id>"); sealed bags can contain restricted data by design (access.json lists every copied source/text, deleted ones flagged, and bag-info carries Wugs-Contains-Restricted), so treat the bag itself as restricted; media files have no per-file access mapping yet (access.json says so) — derive it from MediaTrack→source once the blob branch merges. Lines no seal mode can parse (torn tails included) are copied verbatim and counted in Wugs-Corrupt-Lines. Signed consent forms attached in the People panel are blobs, so every seal copies them into `media/` like recordings; `access.json` lists each under `consent_forms` (media path, name, record, person) flagged restricted, deleted records included, and any consent form marks the bag restricted; a superseded or cleared evidence blob stays in `media/` (the log-derived GC mark keeps it) with no `consent_forms` entry, so listing every ref the log ever wrote under `evidence` is the remaining follow-up.

The other `create_*` conveniences (`create_text`, `add_tier`, …) still return only ids; no validator warns on them today.

Bring back needs the TextGrid still open in Praat (it saves the object by name); if Praat was closed, nothing comes back and Discard is the way out, and if no Praat is running `--send` starts one that shows a script error. Tiers added in Praat, tier type changes and segments Praat cannot hold (overlaps on a tier, untimed) are reported and left alone; a tier missing from Praat's grid deletes nothing. Merging two intervals in Praat keeps the first segment and removes the second; a split keeps the segment on the part whose label did not change; clearing an interval's label removes its segment, clearing a point's mark only empties it. A crash between an apply and the baseline update makes the next return rewrite the same retimes and labels and skip adds already in wugs, except an added item Praat moved again meanwhile, which comes in twice. Only WAV recordings (the blob store holds WAV). Another device's edit to the same field before the return is overwritten by the return (a resolving write; Praat's version is the person's latest). Overlays use Praat's speech defaults with no settings in the app (a high or low voice outside 75–600 Hz shows no pitch), analyse at most a minute of view at a time, draw formants over the waveform (there is no spectrogram yet), and keep their cache until the project's cache is cleared; the first look at a chunk waits for Praat (about a second per minute of audio on the sandbox).
- **Elicitation v1 limits** (`docs/design/ELICITATION.md`): paradigms are row 50's grid in the Lexicon entry editor (limits in that roadmap row), no session planning, no audio per answer, no user-supplied lists; a concept-list load on two devices before a sync gives one list and no conflict rows (equal values); the N/A reason is whatever is in the row's gloss field when N/A is clicked (no separate reason editor); "Use «x»" links the entry's first sense.
- **Gloss panel v1 limits**: one second-language gloss row (the engine takes any number of `gloss:<tag>` fields); an infix inside a root (`s<um>ulat`) is stored as two root morphs around the infix; in a joined breakdown (`un-do`) the root is the longest piece, so a tie needs the marker written apart (`un- do`); analysis suggestions for a very frequent form read every occurrence (about 0.2 s for 2000 occurrences at 100k tokens, release build; the ignored perf test asserts loose bounds); validator 1 compares case exactly, so a suggestion accepted on a sentence-initial capital (`Köpekler` from `köpek` + `ler`) warns until the root's surface is capitalized; lookup keys fold Turkic dotted and dotless i together, so Turkish `kır`/`kir` share suggestions. One bulk commit of 300k ops is about 35% slower than before membership lists (51 s to 70 s at 100k tokens, release, one run), from validators reading the `members` view per token.
- **Conflict queue v1 limits** (item 24): devices are shown as "this device"/"another device" (no names from the roster yet); a membership-list conflict can be settled from the queue (it writes the chosen list) but the Gloss panel's inline offer explains it better; no bulk "keep all mine"; the panel draws 100 cards at a time; conflicts on deleted entities are not listed (nor counted in the badge) but stay in the table and come back with a restore. A token or morph whose segment or text was deleted is still listed (only the entity's own tombstone is checked). STALE also fires when a field gains a version that is not itself a conflict (someone else typing in a merged transcription), so a busy field may need a second click after the reload.
- **Glossing conflicts (item 24 work)**: concurrent analyses of one word, or concurrent tokenizes of one segment, leave one LWW winner and a conflict row on `Token.morphs` / `Segment.tokens`, but no UI offers "use the other version" yet; the losing members are hidden, not lost. Hidden edits show in the Gloss panel with a restore control; restore puts the member back by `pos`, which can leave a restored morph next to its replacement for the linguist to tidy. A restored hidden *word* reappears in the segment but the transcription no longer contains it, so the panel then offers Retokenize, which hides it again; copying its analysis to the retyped word is not built. A hidden edit is reported whenever the editing device differs from the hiding one, even if the hiding device had already seen the edit (a deliberate drop of another device's work still shows); a device that later rewrites the same list takes over as the hider and the row disappears.
- **Timeline v1 limits** (feat/timeline): peak computing runs on the session thread (~1 s per recording hour) and blocks commands while it runs; only the first two channels draw; tier lanes have no vertical scroll, so many tiers overflow; deep zoom past ~190 px/s goes blocky (the finest peaks level is 256 frames; fix with a finer base level or a raw-sample read); `delete_segment` leaves child tokens/morphs alive (validators only warn); `get_text` lists FLEx baseline/free-translation tiers on every text (only ELAN tiers carry `x.elan.text`).
- **Timeline editing v1 limits** (item 59): voice activity is energy only, so loud background noise (wind, generators, other talkers) reads as speech and very quiet speech under a high floor is missed; settings are fixed apart from the utterance/word choice (no sensitivity control yet); word spans split only where the level actually dips for 80 ms, so words run together without a dip (connected speech, a reverberant room) stay one span, and a long stop closure inside a word can split it; a recording with pauses in under ~2% of it has its floor inside the speech and is one span if loud (floor above −35 dBFS), none if quiet, so quiet speech with no pause at all is missed and loud steady noise is one span; the first spans for a recording read the whole WAV once (seconds per hour, off the session thread) and Auto-segment waits for that; WAV only. Snapping applies within 250 ms, only to drawn edges and edges dragged outward of where they were, so a start drawn inside speech further than that stays put (a deliberate cut), and Alt-drag can be taken by some Linux window managers. Undo covers the timeline's own edits (draw, drag, nudge, inline text edit, delete, split, merge, Auto-segment); not Praat's Bring back → Apply, Add track, Import audio, recording, or edits made in other panels, which have their own controls or none. It is per text and in memory (lost on restart or project switch). An undo or redo is refused, writing nothing, when what it would delete or overwrite changed since (anywhere, any device) or a field it writes has an open conflict; a refused entry is dropped, so the edit stays and is changed by hand. The checks are exact: an edit typed and then typed back to the same text, or a nudge out and back, counts as unchanged. A retime undo checks only the edge it moves, so it goes ahead after the text was typed in. Merge and split leave a merged-away segment's words on it (tombstoned with it, back on restore). Unproven by automation, so the owner's hand check: real recordings, Alt-drag on each OS, keyboard focus, refusal toasts. Speech detection's threshold sits at least 55% of the way from the room's floor up to the local speech level, because echo and gain control keep real inter-word dips ~20 dB above the lead-in hiss (a floor-plus-margin threshold made a 6 s Tagalog counting clip one span); soft onsets and releases are reached over frames above floor + margin (≤ 200 ms, at most a third of the gap). Checked on two real counting clips (English: six words found; Tagalog: stop closures split «tatlo» and «apat» in two).
- **Compressed recordings** (item 63): `src-tauri/src/convert.rs` decodes M4A (AAC or Apple Lossless), MP3, FLAC, Ogg Vorbis and AIFF (Symphonia, gapless, so encoder priming is trimmed) to 16-bit WAV in `<project>/cache/convert/` off the session thread, then `session::import_media_named` imports it under the original file name and the temporary WAV is removed (files a crash left there are swept after an hour, at the next import); a file whose first bytes say RIFF/WAVE takes the old WAV path, and one the peaks reader calls unsupported (8-bit, A-law, μ-law, ADPCM) is decoded instead; a chained Ogg that changes format part way is refused. Limits: Opus, WMA, AMR and video containers other than MP4 are not decoded (refused in words); the original compressed file is not kept in the project; 3+ channels are mixed to mono; a file over 4 GiB of decoded PCM is refused; decoding a long file happens before the WAV import, so a 2 h voice memo is decoded, then hashed and peaked like any WAV. Fixtures are synthetic ffmpeg tones (`tests/fixtures/audio/README.md`).
- **Media import and asset scope** (feat/timeline): `import_media` is three intents, not one txn, so a mid-failure leaves a media-less source the picker hides; it also hashes and copies the whole WAV on the session thread (about 1.4 GB read for 2 h stereo) besides the peak compute. Tauri cannot revoke an asset-protocol scope entry, so every project opened during a run stays readable by the webview until restart (low risk under the strict CSP); scope failures are ignored (`.ok()`), costing only playback.
- **Copied-folder detection has two blind spots** (`cache/instance.json`, DECISIONS 2026-11-08): copies made before the marker existed are undetected on both sides, and a filesystem that reuses or does not keep inodes can hide a copy or flag a move.
- **Media capture is audio only, and a take is never deleted except by a confirmed Discard.** Video capture is not built (item 18 stays open for it). Recording writes uncompressed PCM16 WAV (mono or stereo, the AudioContext's own rate) through `capture_*` into `<project>/recordings-pending/`, a durable local folder (not `cache/`; never sealed, never synced; seal copies only `log/` and `blobs/`). Every ~5 s of audio the header sizes are patched and synced, so a crash or power loss leaves a valid WAV missing at most ~5 s. At project open, files no live capture holds are repaired (torn trailing frame trimmed) and listed as **Recovered recordings** in the Media panel: Import (the file goes only after the import's intents commit), Discard (two-step confirm), nothing silent. No code sweeps or auto-deletes; a failed import keeps the capture in a finished state so a second Save retries. Any upload failure, unplugged mic, stopped AudioContext or the 4 GiB WAV size cap (the WAV size fields are u32, so the data chunk tops out just under 4 GiB) stops the take and lands it in the naming row with what was captured, plus a message; Save, Keep for later or an armed Discard follow. The take's state lives in `src/capture/session.ts` (pure lifecycle in `take.ts`), not in the panel, so closing the Media tab does not touch it. While a take is live or unsaved, project open/create/join are refused and the window close is cancelled ("A recording is in progress, stop it first"); a take that outlives its project stays pending and is recovered when that project next opens. The microphone permission is granted only when the webview's current URL is the app's own origin (wry hands the handler no origin, so the closure reads `webview.url()`). A reload or force-quit mid-take is covered by the 5 s patch plus recovery. Unproven by automation, so the owner's hand check: real mic, unplug, close guard, WebView2/WKWebView prompt.
- **Linux recording is unverified.** WebKitGTK ships `enable-media-stream` off and wry 0.57 does not turn it on, so `navigator.mediaDevices` is likely missing there and the Media panel says so. Windows (WebView2) and macOS (WKWebView; `src-tauri/Info.plist` carries `NSMicrophoneUsageDescription`) are expected to work; `on_permission_request` allows only Microphone. Needs a hand check on each OS.
- **Installers are unsigned** (SmartScreen / Gatekeeper warnings); code signing waits on certificates (`docs/INSTALL.md`). The in-app updater signs **updates** only (minisign, DECISIONS 2026-11-10).
- **Updater v1 limits**: unproven until the first signed tag (check list in `docs/INSTALL.md`, "First signed release"); only releases published after one built with the updater can update it (0.1.0 is the first published release; earlier unpublished builds update by hand once); a `.deb` install is offered updates but the plugin installs them with `pkexec dpkg -i`, which asks for a password, and an AppImage needs write access to its own file; "Later" lasts until the next start; the size shown comes from a HEAD request and is left out if it fails; the Windows installer closes the app itself (the layout is flushed first, and the project is closed after the session thread's queue drains, so an install can wait on a long command such as a sync); the macOS payload is our own tar of the `.app`, not `tauri build`'s, so check the first macOS update by hand; release notes are the tag message as written (shown as plain text).
- **Conflicts follow write heads (item 49)**: a write closes the versions it names. A person's direct edit or pick (`Txn::resolving()`: set_gloss, link_sense, pick_sense, apply_analysis of one word, choose_member_list, restore_member, set_segment_times, set_access, edit_content, the lexicon field edits (set_lexeme_field, set_homograph, number_homographs, set_sense_gloss, set_sense_text); `Txn::set_resolving` for one field, e.g. a retyped token `form` inside retokenize) names every open version, so it resolves the field's conflicts everywhere; plain txns (bulk apply-to-unanalysed, the token list of tokenize/retokenize, split_morph, importers, anything new unless it is a direct edit) name only `[base]` and leave conflicts open. "Accept the winner" in item 24 is a resolving `set` of the shown value; fields with no resolving writer yet (text title, tier fields) need item 24's prompt to close. Op schema is 2; a schema-1 head closes once its own actor wrote the field again under schema 1 (`legacy_writes`). A txn whose HLC is >24 h ahead is held in quarantine before it applies (`clock drift: …`) and retried later; opening a project absorbs its own log's HLCs without the drift check (`Clock::absorb`). `IngestReport.conflicts` / `ApplyStats.conflicts` count newly opened rows. A degraded text-edit (no or corrupt loro) that wins keeps its own value; `text_unmerged` flags fields whose updates no longer merge as a set (their value is the winner's own `resolved`, kept per update in `text_updates`, and `Txn::text_edit` falls back to plain text there). Limits: retokenize writes a token `form` only when the typed form differs from the winner, so retyping the winning spelling leaves a form conflict open (item 24's "keep this one" must be a resolving set of the shown value); a device whose clock ran ahead and was corrected keeps issuing HLCs past its own newest op after reopen (`Clock::absorb`), so peers hold its new txns until real time catches up; no test covers a corrupt (rather than missing) loro payload, though both take the same LWW path; a replica that holds a write and a later write that superseded it only through an intermediate write it has not received shows a conflict until the intermediate arrives (over-reports, never hides); ops written before `heads` existed close only their `base`, so a pre-upgrade edit that followed a conflict does not close it; the projection keeps no record of closed conflicts (the log has every value).
- **Cache rebuild ping-pong with and without a normalizer**: the cache version folds in whether a normalizer is installed, so opening one project alternately from builds with and without `wugs-unicode` replays each time. Record a normalizer id/version in cache meta instead.
- **Bulk commit slowed with membership lists** (300k ops: 51 s to 70 s): validators read the `members` view per token. The 500k replay gate still passes (cold replay 45.0 s ≤ 60 s on feat/glossing). Batch the view reads per txn if imports hurt.
- Remote branch deletion is blocked by the session proxy; merged `feat/*` branches may linger — delete via GitHub UI.
